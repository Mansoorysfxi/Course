# Exercise 01 — Run, Inspect, and Clean Up a Real Container (Easy)

**Concepts this exercise uses (all taught in
[`lessons/01-containers-vs-vms-and-your-first-container.md`](../../lessons/01-containers-vs-vms-and-your-first-container.md)):**
`docker run` (`--detach`, `--name`, `--publish`), `docker ps`,
`docker logs`, `docker exec -it`, `docker stop`, `docker rm`,
`docker images`.

**Where to work:** any terminal with `docker` working (Lesson 00's setup
— your WSL2 Ubuntu shell, or plain PowerShell, either is fine).

This is this module's easiest exercise — if you read Lesson 01 and typed
along with its own worked example, every command below should already
feel familiar. The goal here is doing it once more, entirely on your
own, with a **different** image, to confirm you actually retained the
commands rather than just watched them work.

## Your task

Using **`httpd:alpine`** (the official Apache HTTP Server image — a
different web server than Lesson 01's `nginx:alpine`, on purpose, so you
can't just blindly repeat memorized commands without understanding what
each one does):

1. Run a **detached**, **named** container from `httpd:alpine`, publishing
   its internal port `80` to port **8090** on your own machine.
2. Confirm it's running, with `docker ps`, and note its container ID.
3. Use `curl` against the port you published to confirm you get a real
   HTTP response back (Apache's own default page).
4. View its logs, and confirm your `curl` request from step 3 shows up
   in them.
5. Open an interactive shell **inside** the running container (`docker
   exec -it ... sh`) and run `ps aux` from inside it. Note how few
   processes you see, and be ready to explain why.
6. Exit that shell (the container should keep running).
7. Stop the container, then confirm with `docker ps -a` that it still
   exists, just in a stopped state.
8. Remove the stopped container, then confirm with `docker ps -a` that
   it's genuinely gone.
9. Confirm the **image** itself (`httpd:alpine`) is still present with
   `docker images`, even though the container is gone.

## Acceptance criteria

- [ ] A container from `httpd:alpine` was successfully run, named, and
      reachable via `curl` on port 8090.
- [ ] You can show the log line generated by your own `curl` request.
- [ ] You can explain, in your own words, why `ps aux` run *inside* the
      container showed so few processes compared to your host machine.
- [ ] The container was cleanly stopped and removed; the image was not.
- [ ] You can explain the difference between what `docker stop` and
      `docker rm` each actually did.

## Hints

<details>
<summary>Hint 1</summary>

The command shape is identical to Lesson 01's own `nginx:alpine`
example — only the image name, container name, and host port need to
change. Re-read that lesson's "Running your first real container"
section if you're stuck on the exact flags.

</details>

<details>
<summary>Hint 2</summary>

`httpd:alpine`'s default page is much simpler than Nginx's — don't worry
if the HTML you get back from `curl` looks minimal or different in
wording; what matters is that you get a real HTTP response at all, not
a connection error.

</details>

<details>
<summary>Hint 3</summary>

If `docker exec -it <name> sh` says something like "OCI runtime exec
failed: exec: bash: executable file not found," you tried `bash`
instead of `sh` — Alpine-based images (like this one) don't include
`bash` by default, only the smaller `sh`, exactly the same gotcha
Lesson 01 called out for `nginx:alpine`.

</details>
